# 保留日历间隔的日期平移

text 列可设规则 {"shift_days":365}。非 null 值按前推公历平移指定整数天，时间后缀原样保留；关联日期键必须使用相同规则。最大偏移绝对值 3,652,058 天，结果必须在 0001-01-01 至 9999-12-31。越界拒绝，没有回绕或截断。

支持 YYYY-MM-DD；也支持后接 T 或空格、HH:MM:SS、可选 1–9 位小数秒、可选 Z。允许无时区墙钟文本。小时 00–23，分秒 00–59；不支持时区偏移/名称、夏令时换算、闰秒、缩写日期或负年份。输入与输出均检查日历有效性。这里只参考 [RFC 3339](https://www.rfc-editor.org/rfc/rfc3339) 的日期/时间分量，不声称完整支持该 RFC，未复制实现或样例。

相同偏移保留天数差、顺序和后缀，不计算本地时区对应的 UTC 时间，涉及夏令时时不承诺真实经过秒数不变。这是可见的日期扰动，不是加密或匿名保证。null 保持 null，普通 keep 列不限制日期格式。

完整真实数据演练：

    moon run dev/dates_workflow.mbtx -- wasm

它读取 Chinook 策略到临时目录，仅将 BirthDate、HireDate、InvoiceDate 改为平移 365 天，运行 export/verify，检查 428 个日期、已知员工日期、时间后缀、行数和未指定金额。原策略和数据不改动；Native CI 运行相同流程。
